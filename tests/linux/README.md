# tests/linux

Scripts for an ephemeral Ubuntu 24.04 VM (Debian 12 should work too; Ubuntu 22.04 cannot, its polkit ignores .rules files) with systemd, cgroup v2, sudo and network access. They create the `supavise` user, install units under `/etc/systemd/system`, download the real artifacts and start real clusters. Do not run them on a machine you care about; development machines run the exec-backend tests instead (`internal/lifecycle`, `SUPAVISE_TEST_UNPACKED`). Each script exits non-zero on any failure.

| Script | CI job (`linux.yml`) | What it checks |
|---|---|---|
| `systemd-smoke.sh` | `systemd-smoke` | System init and two projects under real units: health, containment from inside the namespaces, the WAL relay (archiving, foreign-ref refusal, fail-closed with the daemon down), base backup and restore of a clone, the instance metadata service denied to every unit, pg_cron, a project through the Management API, pause, resume, key rotation, `kill -9` recovery, delete. |
| `fleet-smoke.sh` | `fleet-smoke` | The shared services under systemd and through the daemon: tenant registration, REST and Storage through the proxy, pooler logins, Realtime, `kill -9` recovery, the metadata service denied to each, a Storage object and an Edge Function restored from backup, project delete, `fleet stop`. Skips Studio (no slim artifact). |
| `functions-smoke.sh` | `functions-smoke` | Edge Functions under systemd: `supavise functions dev`, then `tests/functions/run.sh` (real `supabase functions deploy`, supabase-js, JWT on and off, secrets, isolation of crash, runaway and memory-hog functions, redeploy, delete) and the edge-runtime unit's hardening. Installs the Supabase CLI release (checksum-verified). |
| `settings-smoke.sh` | `settings-smoke` | Dashboard writes under systemd with a PAT: auth, PostgREST, Storage, Realtime and pooler settings, Postgres settings (including one that needs a restart), key revocation, a database password reset, and that pause and resume keep every setting. |
| `compute-smoke.sh` | `compute-smoke` | Compute sizes on a loop-mounted XFS volume with `prjquota`: resize (limits, Postgres settings and pooler pool change, data survives), a size the node cannot hold refused, a failed downsize rolled back, and a per-project disk size enforced as an XFS quota. |
| `backups-smoke.sh` | `backups-smoke` | Backups and point-in-time restore through the Management API: the backup list, PITR to a time between two writes, refusals while RESTORING, times outside the span refused, restore from a listed base backup. |
| `upgrade-smoke.sh` | `upgrade-smoke` | Project upgrades under systemd: projects kept on older GoTrue and PostgREST releases by a node update, an upgrade onto a release that does not start (rolled back, data intact), the good upgrade through `POST /v1/projects/{ref}/upgrade`, `supavise projects upgrade --all --yes`, and `supavise artifacts gc`. |
| `upgrade-e2e.sh` | `upgrade-e2e` | The node upgrade on a node `deploy/install.sh` installed from the previous release (`upgrade-e2e-build.sh` builds it and the releases to upgrade to): `--check` and `--plan` change nothing, refusals exit 2, the upgrade itself, a release whose daemon dies or whose PostgREST does not start (exit 3), a release that renders a service differently, and `supavise rollback` (refused while the registry holds an unknown migration). |
| `roles-smoke.sh` | `roles-smoke` | Members and roles under systemd: invitations by role, `/platform/profile/permissions`, what each role may do with PATs, organization delete, project-scoped roles, the real MCP server and Supabase CLI as Read-only and as Owner, and invitation mail through `[mail]`. |
| `sso-smoke.sh` | `sso-smoke` | Single sign-on against a real SAML identity provider (SimpleSAMLphp in a container, amd64 only; `tests/linux/sso/saml_walk.py`): `supavise sso add`, sign-in, approval of an unmapped domain, a removed user, provider removal, and a project's own SAML provider with the Supabase CLI. `internal/api/sso_integration_test.go` is the same walk on a development machine. |
| `install-e2e.sh` | `install-e2e` | `deploy/install.sh` on a fresh VM and everything after it: signature and checksum refusals, the install, the claim flow, a project with a PAT, REST and Storage through the proxy, the pooler, `supavise status` and `/healthz`, maintenance notices, idempotent re-runs, `self-update` and its rollback, and `update config`. `deploy/README.md` describes the install path. |
| `os-updates.sh` | `os-updates` | `supavise system os-updates` in containers (Ubuntu 24.04, Debian 12 and 13): what apt and `unattended-upgrade` read, a repeat run, turning it off, and that a foreign file is left alone. |
| `branching-xfs.sh`, `branching-egress.sh` | `branching-xfs` | `branching-xfs.sh` runs without systemd (the exec supervisor, as an unprivileged user): branch clones with FICLONE on a loop-mounted XFS reflink volume and by base-backup restore on ext4, plus the full branching scenario. `branching-egress.sh` checks under systemd that a branch with denied egress cannot reach the outside world (`IPAddressDeny` on its Postgres unit, its cron jobs paused, the restriction surviving pause, resume and reset; `--allow-egress` lifts it). |
| `footprint.sh` | `footprint` workflow (manual) | Grows to 10, 25 and 50 projects and records create time, per-project PSS and RSS, `supavise.slice` memory, disk per project, resume time and whole-node cold start (`$LOG_DIR/footprint.md`). The results are in `docs/reference/footprint.md`. |
| `lib.sh` | | Shared helpers. |

```
sudo SUPAVISE_BIN=./bin/supavise-linux-amd64 tests/linux/systemd-smoke.sh --teardown
sudo SUPAVISE_BIN=./bin/supavise-linux-amd64 tests/linux/footprint.sh --sizes "10 25 50" --class default
```

`SUPAVISE_BIN` is a Linux build (`make build-linux`); without it the scripts build one with go. Logs (journal, unit list, host facts, df) stay in `$LOG_DIR` (default `/tmp/supavise-linux-logs`). `SUPAVISE_DOMAIN` sets the config domain (default `supavise.test`; TLS is off, nothing needs DNS).
